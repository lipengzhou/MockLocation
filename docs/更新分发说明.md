# 更新分发说明

## 更新检查

应用不再直接请求 GitHub Releases API 检查新版本，避免未认证 API 的 403 限流问题。

客户端读取固定的 jsDelivr 静态清单：

```text
https://cdn.jsdelivr.net/gh/lipengzhou/MockLocation@main/release/update.json
```

清单文件位于仓库：

```text
release/update.json
```

每次正式发布后，需要把清单里的版本号、下载地址、文件大小和 SHA256 同步更新，并推送到 `main` 分支。

## 清单格式

```json
{
  "tagName": "v1.8",
  "versionName": "1.8",
  "versionCode": 9,
  "title": "MockLocation 1.8",
  "releaseUrl": "https://github.com/lipengzhou/MockLocation/releases/tag/v1.8",
  "downloadUrl": "https://github.com/lipengzhou/MockLocation/releases/download/v1.8/MockLocation-1.8-release.apk",
  "assetName": "MockLocation-1.8-release.apk",
  "assetSizeBytes": 38753279,
  "sha256": "e235d561853f421a19b89ea390389587273fcad7ef93cc2a30bde7d03c1db1d9",
  "releaseNotes": "优化设置页返回行为、权限引导说明和弹窗底部间距。"
}
```

客户端当前使用这些字段：

- `tagName`
- `versionName`
- `title`
- `releaseUrl`
- `downloadUrl`
- `assetName`
- `assetSizeBytes`
- `releaseNotes`

`versionCode` 和 `sha256` 暂时用于发布校验和人工排查。

## APK 下载地址

当前 `MockLocation-1.8-release.apk` 约 37MB，超过 jsDelivr GitHub 代理默认的单文件 20MB 限制，因此 APK 下载地址继续使用 GitHub Release asset：

```text
https://github.com/lipengzhou/MockLocation/releases/download/v1.8/MockLocation-1.8-release.apk
```

如果后续 APK 能稳定控制在 20MB 以下，可以把 APK 放到公开仓库路径，并将 `downloadUrl` 改为 jsDelivr：

```text
https://cdn.jsdelivr.net/gh/lipengzhou/MockLocation@release-cdn/releases/v1.8/MockLocation-1.8-release.apk
```

这要求 `release-cdn` 分支中实际存在：

```text
releases/v1.8/MockLocation-1.8-release.apk
```

不建议把大 APK 持续提交到 `main` 分支，避免源码仓库膨胀。

## 发布后验证

发布后先验证清单可访问：

```bash
curl -I https://cdn.jsdelivr.net/gh/lipengzhou/MockLocation@main/release/update.json
curl https://cdn.jsdelivr.net/gh/lipengzhou/MockLocation@main/release/update.json
```

再验证 APK 下载地址：

```bash
curl -I https://github.com/lipengzhou/MockLocation/releases/download/v1.8/MockLocation-1.8-release.apk
```

如果更新了 `main` 分支但 CDN 仍返回旧清单，可以等待 jsDelivr 缓存刷新；紧急发布时建议改用新的 tag 或专用分发分支提交，避免依赖同一个 mutable URL 的即时刷新。
